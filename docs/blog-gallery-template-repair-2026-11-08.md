# 博客画廊预览与内置模板修复

用户报告画廊长时间显示“正在准备博客空间”，随后示例人物仍只显示相似的资料卡片。实际检查发现，12 个 iframe 中只有真实成员页面具有画廊需要的 `.blog-gallery-embed` 标记，其他 11 个示例缺少该标记。HTML 预处理因此回退到 iframe URL，但加载观察器仍无法识别页面，最终留下身份占位卡片。并非用户资料或模板丢失。

## 修复

- 画廊示例使用 `/blogs/showcase/:handle?template=builtin`。完整示例和内嵌预览共用 `showcasePageData`、`applyBlogTemplate`、`applyBlogAppearance` 与 `BlogTheme`，对应编辑器原有的六种页面排版与八种视觉主题。
- `embed=gallery` 返回带明确标记、直接服务端渲染的只读模板文档；旧的内嵌链接同样兼容。
- 画廊为已有查询参数的链接正确追加 `&embed=gallery`。预热接口和客户端允许列表使用相同地址，保留严格的公开预览 URL 范围。
- 实际成员继续显示自己的已发布设计。示例不创建成员账号、不保存用户数据、不计入成员访问。
- 原有独立作品集研究仍在不带查询参数的示例地址保留；下方产品展示的引用没有被删除或替换。

原有同源 iframe 限制、只读模板的无脚本 sandbox、两路下载、逐帧处理、缓存容量与画廊空间构图保持原实现。本次不增加外部素材或变更许可。

## 回归验证

- 674 项单元测试通过，生产构建和类型检查通过。
- 新增 `npm run test:gallery:http`：检查所有 11 个示例的真实服务端 HTML，确认画廊标记、完整模板内容、模板及主题属性、同源内嵌响应头，以及文档大小符合预览缓存预算；完整示例链接与预览模板一致。
- HTTP 检查兼容真实成员增加后占用更多画廊位置，不要求预热列表永远包含全部示例。
- 浏览器分别检查从首页导航、带锚点访问及刷新；当前一位真实成员和 11 个示例的 12 张预览均完成加载，预处理后的 iframe 脚本数为零。
- 1453×959、390×844、2048×978 下检查画廊与选中状态，所选示例正确居中；完整模板在桌面和手机布局中都能打开，未观察到横向页面溢出。
- 独立复核对本次加载与模板接入修复给出 `ship`，未列出必须修复项；范围不包含其他进行中的样式改动或全站审计。

上述浏览器结果是本机验收范围，不代表公网容量或所有终端保证。本机截图与复核记录不随代码发布。
