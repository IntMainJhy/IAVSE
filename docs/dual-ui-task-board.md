## 阶段 2：隔离与最小可运行骨架

- [ ] 用户确认新写公开 UI 自身的许可范围；未确认前不更改现行 LICENSE。
- [x] 经用户要求提前建立公开 Git 根目录之外的私有工作区，核对 Private、远端归属及首次推送；尚未建立运行入口。
- [ ] 定义最小页面输入、状态与动作契约。
- [ ] 用一个页面证明共享逻辑可分别装配公开与 Pro UI。
- [ ] 在没有 Pro 文件和素材库 Key 的环境中验证公开骨架可构建与启动。
- [ ] 为旧公开适配材料的后续处理留下明确记录，不擅自清理 Git 历史。

完成依据：两版装配边界成立，公开构建没有隐藏的私有依赖。

## 阶段 3：先实现 Pro UI

- [ ] 首页：平台定位、资源搜索与三个产品入口。
- [ ] 社区：信息流、搜索筛选、投稿与真实空状态。
- [ ] 博客空间：恢复 3D 开场、选中聚焦、完整博客入口及普通目录回退。
- [ ] 资源目录与详情：保留来源、许可、过滤与查询行为。
- [ ] 关于、账号、管理与编辑器外壳：按实际任务适配，不覆盖作者内容。
- [ ] 每页完成实际功能、桌面／手机、键盘与减少动态验收。

完成依据：Pro 材料仅在私有工作区，页面功能与既有业务契约一致，所用材料有真实交付和授权记录。

## 阶段 4：再完成公开 UI

- [ ] 根据共同产品需求原创设计平台外壳，不继续套个人作品集结构。
- [ ] 实现与 Pro 对等的首页、社区、资源、博客空间与其他平台页面。
- [ ] 审查并复用权属明确的自写 3D 逻辑，使用核准的开源动画实现。
- [ ] 保留作者博客、画布、语言和主题内容边界。
- [ ] 补齐第三方版本、许可、署名与自写 UI 的许可说明。
- [ ] 检查公开实现未混入 Pro 源码、付费提示词、资产或其改写移植版本。

完成依据：公开 UI 是完整可运行实现，不是需要私有代码才能显示的占位页面。

## 阶段 5：两版对照验收

- [ ] 账号、权限、发布、审核、收藏关注与编辑行为一致。
- [ ] 用户数据、公开快照、上传和作者主题不因切换 UI 被重置。
- [ ] 相关回归、类型检查与生产构建通过。
- [ ] 桌面与手机检查完成，空、加载、失败、无权限和减少动态有可用状态。
- [ ] 公开版在干净环境按公开文档可独立运行。
- [ ] 公开源代码、生成物、测试数据、缓存与文档没有受限材料或凭据泄露。
- [ ] 文档和截图反映实际实现，不引用历史测试数量作为本轮通过依据。

## 阶段 6：构建与交付

- [ ] 公开版发布所需源码、部署说明、许可与署名完整。
- [ ] 私有版固定共享核心提交与材料版本，完成私有构建验证。
- [ ] 若向第三方交付 Pro 完整应用，先记录许可允许范围与实际交付内容。
- [ ] 回滚路径成立，不以清空数据库恢复 UI。
- [ ] 分别核对公开同步、私有同步、部署与成品分发，不将其混为一项完成状态。
